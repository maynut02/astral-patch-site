# 모드 허브 초안

`/mod`는 모드 목록·검색·등록 화면이고, `/mod/1`처럼 숫자 ID를 사용하는 `/mod/:id`는 모드 상세·수정 화면입니다. 페이지 파일은 각각 `app/pages/mod/index.vue`, `app/pages/mod/[id].vue`입니다. 등록을 완료하면 새 모드의 상세 페이지로 이동합니다.

로그인한 사용자가 공개 GitHub 저장소를 등록합니다. 등록·수정 화면에는 저장소 URL, 모드 이름, 지원 플랫폼만 표시하며 세 항목 모두 필수입니다. 지원 플랫폼은 Windows 또는 Android 중 하나 이상 선택해야 합니다. 등록자는 자신의 모드를 수정·삭제할 수 있고, 관리자는 모든 모드를 수정·삭제할 수 있습니다. 관리자 수정 후에도 원래 등록자는 유지됩니다. `내 모드`는 수정 권한과 별개로 본인이 등록한 모드만 표시합니다. 같은 저장소는 중복 등록할 수 없습니다.

삭제는 상세 페이지의 확인 창에서 진행하며 모드 허브의 등록 정보를 삭제합니다. 목록에서 제거되고 해당 상세 주소는 더 이상 조회되지 않습니다. 같은 GitHub를 다시 등록하면 새 숫자 ID를 받습니다.

## DB 준비

기존 migration 실행 절차로 `database/migrations/0013_mod_hub.sql`과 `0014_mod_numeric_ids.sql`까지 적용해야 등록·조회가 동작합니다. 웹 서버는 테이블을 자동 생성하지 않습니다. 계정을 탈퇴하면 모드는 익명 계정으로 이전되어 설명과 다운로드 링크가 유지됩니다.

모드 ID는 PostgreSQL의 `bigint GENERATED ALWAYS AS IDENTITY`로 생성합니다. 빈 테이블에서는 1부터 시작하며, 기존 모드는 생성 시각 순으로 번호를 부여하고 이후 등록은 마지막 번호 다음부터 이어집니다. 생성 시각이 같으면 기존 UUID 순으로 정합니다. 기존 모드의 정보와 등록자는 유지되지만 UUID를 사용하던 상세 URL은 숫자 ID 주소로 변경됩니다. 삭제나 등록 실패로 번호가 비어도 재사용하지 않습니다. API에서는 큰 정수의 정밀도를 유지하도록 숫자 ID를 십진수 문자열로 반환합니다.

## GitHub 연동

- 목록 카드의 설명과 소개 검색에는 GitHub About을 사용합니다. About이 비어 있거나 조회한 설명이 없으면 카드에 `설명 없음`을 표시하며, 기존 DB의 요약으로 대체하지 않습니다.
- 목록에서는 README·커밋·릴리즈를 조회하지 않고 About만 가볍게 조회합니다. 서버에서 저장소별로 5분 캐시하며, 한 목록 요청에서는 최대 6개 저장소를 동시에 조회하고 DB에서 반환한 순서를 유지합니다. 일시적인 GitHub 조회 실패 시 마지막으로 조회한 설명을 사용하고, 캐시도 없으면 빈 설명으로 처리해 목록 전체 조회는 계속합니다. 비공개로 전환되거나 찾을 수 없는 저장소의 설명 캐시는 비웁니다.
- 상세 페이지의 한 줄 소개는 GitHub About 설명을 그대로 표시합니다.
- 소개 탭에서 기본 브랜치의 README를 표시하고, 커밋 탭에는 최근 커밋 10건을 표시합니다.
- 커밋 탭은 기본 브랜치를 먼저 표시하며, 브랜치가 여러 개이면 선택 메뉴에서 브랜치를 바꿀 수 있습니다. 브랜치별 최근 커밋 10건을 조회하고 서버에서 저장소·브랜치별로 5분 캐시합니다. `전체 보기`는 선택한 브랜치의 GitHub 커밋 목록으로 연결합니다.
- 공개 릴리즈를 20건씩 불러오고 이전 버전을 더 불러올 수 있습니다. 사전 릴리즈는 별도로 표시합니다.
- 파일 다운로드는 GitHub 릴리즈의 첨부 파일로 직접 연결합니다. 첨부 파일이 없는 릴리즈도 표시합니다.
- README의 상대 링크와 이미지는 해당 저장소의 경로로 연결합니다. 원문 HTML은 실행하지 않습니다.
- 상세 화면 조회 시 GitHub를 확인하고 저장소별 정보를 5분 캐시합니다. 별도의 주기적 워처나 웹훅은 아직 없습니다.
- `GITHUB_TOKEN`은 선택 사항이며 기존 릴리즈 연동과 공유합니다. 서버에서만 사용하고 비공개 저장소는 등록·표시하지 않습니다.
- GitHub에 연결할 수 없어도 등록된 상세정보를 표시하며, 연결 저장소를 변경하지 않는 정보 수정은 가능합니다.

## API

| 요청 | 용도 |
| --- | --- |
| `GET /api/mods` | 모드 최대 200개, GitHub About, 실제 등록자 여부(`isOwner`), 수정·삭제 권한 |
| `POST /api/mods` | 로그인한 사용자의 모드 등록 |
| `GET /api/mods/:id` | 모드 상세정보와 GitHub 정보 |
| `PATCH /api/mods/:id` | 등록자·관리자의 정보 수정 |
| `DELETE /api/mods/:id` | 등록자·관리자의 모드 삭제 |
| `GET /api/mods/:id/releases?page=2` | 이전 릴리즈 조회 |
| `GET /api/mods/:id/commits?branch=develop` | 선택한 브랜치의 최근 커밋 조회 |

변경 요청에는 same-origin 검사, DB의 최신 로그인 정보 검사, 사용자별 요청 제한을 적용하며 등록·수정은 JSON 본문을 받습니다. 삭제는 본문 없이 요청할 수 있습니다. 수정·삭제 쿼리에서도 현재 DB 계정의 등록자·관리자 권한을 확인해 처리 도중 권한이 바뀌면 변경을 거부합니다.

목록 응답의 `ModListEntry`는 기존 `ModEntry`에 표시용 `githubDescription`을 추가합니다. DB의 `summary`·`description`과 저장 요청 형식은 유지하며, GitHub About을 DB에 덮어쓰지 않습니다. 조회자별 `canEdit`을 보호하기 위해 목록 API 응답은 계속 `no-store`로 반환하고, GitHub 설명만 서버에서 캐시합니다.

## 검증

```sh
pnpm test:mods
pnpm check
```

후속 개선 후보는 목록 서버 페이지네이션, 태그·카테고리, 설치 환경별 파일 분류, GitHub 변경 알림입니다.
